# Task 5 — Add (or Remove) a Custom Finder of an Existing Persistable Object

Use this workflow when the object's API, CORE and tests already exist (Tasks 2–4) and the user wants a new finder (`findByNameExact`, `findByMediaGroup`…), or wants one removed. When the finder is part of creating the object, Tasks 2–4 already cover it; this playbook has the code of each layer for both cases.

A custom finder is one method that crosses every layer, and each layer has a different job:
- the API declares it;
- the Client API exposes it without the `SecurityContext`;
- Tier 1 only delegates;
- Tier 2 validates the parameters;
- Tier 3 runs a JPA `@NamedQuery` on a column of the entity;
- that column exists only because the transfer delegate copies the field there.

Missing one link compiles fine and fails at runtime: an unknown named query, an always-empty column, a method the client can't reach. So add every layer, in order, in a single pass.

## Step 5.0: Pin down the finder
- **What it filters on.** Read the model: the finder filters on fields that exist in it. If a field is missing, add it first (Task 6), or ask whether to.
- **Don't duplicate what exists.** Every Find service already has:
  - from r01f `FindServicesForModelObject`: `findAll`, `findByCreateDate`, `findByLastUpdateDate`, `findByCreator` and `findByLastUpdater`;
  - from `OG00IsFindServicesForPersistableObject`: `findAllSummarized`.

  Lookup by OID or business ID is CRUD's `load` / `getOidOf`. If the user's finder is one of these, point them to it instead.
- **Name and signature.**
  - Follow the sample: name it `findBy{Field}` (`findByNameExact` for an exact string match), take `SecurityContext` first and then one parameter per filtered field, and return `FindResult<{apiAppCode}{PersistableObj}>`.
  - For a reference to another object, take its **OID** (`OG10MediaGroupOID mediaGroupOid`), which is what the column stores and is always set, while a Ref may carry only the business ID.
  - Ask only if the matching rule isn't clear: exact or `LIKE`, case-sensitive or not, which fields are optional. Otherwise use exact equality and say so in the report.
- **Prerequisites.** If the object's Find interface or Find DAO is missing, stop and say which (the object needs Tasks 2–3 first).

## Step 5.1: Add the finder, layer by layer
The worked example is `findByMediaGroup` of `OG10Media`: component `media-register`, API `OG10`, CORE `OG11`, tests `OG99`. It finds the media that belong to a media group, through the `_mediaGroupRef` field of the model. Replace the names with the object's own, and open the sample counterpart (`findByNameExact` of `SamplePersistableObj`, Section 6 of `SKILL.md`) when in doubt.

The code is already in the house style: spaces, parameters aligned under the first one, fluent chains on the root dot, JPQL keywords right-aligned. When a name has a different length, realign as [`r01-java-formatter`](../../r01-java-formatter/SKILL.md) says.

The classes generated by Tasks 1–4 have placeholder comments where finders go:
- the Find interface: `// add here the custom finders…`;
- the entity: `// add here a @Column…`;
- the transfer delegate: `// fields exposed outside the descriptor: none…`;
- the test: `// add here a block for every custom finder…`.

Replace the placeholder with the code when you add the first finder.

Nothing needs registering in Guice, Spring or `persistence.xml`. The Find service, delegate and DAO are already wired, and the entity is already listed. The table gets the new column through `hbm2ddl.auto: update`.

### 1. API — Find service interface
`OG10FindServicesForMedia` in `{domain id}.{system id}.{component id}.api.interfaces.media`, in the empty section after the header:

```java
    /**
     * Finds the {@link OG10Media} that belong to a {@link OG10MediaGroup}
     * @param securityContext
     * @param mediaGroupOid
     * @return
     */
    public FindResult<OG10Media> findByMediaGroup(final SecurityContext securityContext,
                                                  final OG10MediaGroupOID mediaGroupOid);
```
Imports:
- `r01f.model.persistence.FindResult`
- `r01f.model.security.context.SecurityContext`
- the OID: `ogov.communic.mediaregister.api.model.oids.OG10MediaRegisterOIDs.OG10MediaGroupOID`
- the referenced model class, if the Javadoc links it from another package.

### 2. API — Client API Find delegate
`OG10ClientAPIDelegateForMediaFindServices` in `{…}.api.media`. It declares the same finder without `SecurityContext`, returns the objects, and throws if the call failed:

```java
    /**
     * Finds the {@link OG10Media} that belong to a {@link OG10MediaGroup}
     * @param mediaGroupOid
     * @return
     */
    public Collection<OG10Media> findByMediaGroup(final OG10MediaGroupOID mediaGroupOid) {
        return this.getServiceProxyAs(OG10FindServicesForMedia.class)
                   .findByMediaGroup(this.getSecurityContext(),
                                     mediaGroupOid)
                   .getOrThrow();
    }
```
Imports: `java.util.Collection` and the OID.

### 3. CORE — DB entity: column, index and named query
`OG11DBEntityForMedia` in `{…}.core.db.entities.media`.

**Column.** Add one in the `FIELDS` section for each filtered field that doesn't have one yet. Store a reference as the referenced OID string, sized like the base `ID` column:

```java
////////// --- Media group
    @Column(name="MEDIAGROUP_OID",length=OID.OID_LENGTH,
            nullable=true,
            insertable=true,updatable=true) @Basic
    @Getter @Setter private String _mediaGroupOid;
```
Imports: `jakarta.persistence.Basic`, `jakarta.persistence.Column`, `lombok.Getter`, `lombok.Setter`, `r01f.oids.OID`.

**Index.** Add one to `@Table.indexes` when the finder will be used often or the table is large.
- Name it `{TABLE}IDX_BY_{COLUMN}` and put it after the existing `…IDX_BY_ID`.
- Add a comma after the closing parenthesis of `…IDX_BY_ID`, before its comment.

```java
@Table(name = "OG11MEDIA",
       indexes = {
            @Index(name = "OG11MEDIAIDX_BY_ID",
                   columnList = "ID",unique = true),    // the id is unique
            @Index(name = "OG11MEDIAIDX_BY_MEDIAGROUP_OID",
                   columnList = "MEDIAGROUP_OID")
       })
```

**Named query.** Name it `{entity class}.{finder name}`.
- If the entity has no `@NamedQueries` yet, add it after `@Table` (and its commented `@IdClass` block) and before `@Accessors`, as in the sample.
- The JPQL refers to the entity class and its Java fields (`dbMedia._mediaGroupOid`), never to table or column names.

```java
@NamedQueries({
    @NamedQuery(name = "OG11DBEntityForMedia.findByMediaGroup",
                query = "SELECT dbMedia " +
                          "FROM OG11DBEntityForMedia dbMedia " +
                         "WHERE dbMedia._mediaGroupOid = :mediaGroupOid")
})
```
Imports: `jakarta.persistence.NamedQueries`, `jakarta.persistence.NamedQuery`. A second finder is another `@NamedQuery` in the same list, separated by a comma.

### 4. CORE — transfer delegate
`OG11ModelObjToDBEntityTransferDelegateForMedia` in `{…}.core.db.transfer.media`, in `setDBEntityFieldsFromModelObject(...)` after the `super` call.
- It copies every column on each create and update.
- Nothing reads the column back into the model: the model is loaded from the XML descriptor.
- Without this copy the column is always `null` and the finder never finds anything.

```java
        // fields exposed outside the descriptor
        dbEntity.setMediaGroupOid(modelObj.getMediaGroupRef() != null ? modelObj.getMediaGroupRef().getOid().asString()
                                                                      : null);
```
If a Ref can arrive with only its business ID, the OID here is `null` and the object won't be found by this finder. Either say so in the report, or, if the user wants, complete the Ref first: the component's `{apiAppCode}{PersistableObj}RefSolver` resolves ID → OID.

### 5. CORE — Find DAO (Tier 3)
`OG11DBFindForMedia` in `{…}.core.db.dao.media`. Run the named query, then turn the entities into model objects with `FindResultBuilder` (the DAO itself is the transformer):

```java
    @Override
    public FindResult<OG10Media> findByMediaGroup(final SecurityContext securityContext,
                                                  final OG10MediaGroupOID mediaGroupOid) {
        TypedQuery<OG11DBEntityForMedia> q = this.getEntityManager()
                                                 .createNamedQuery("OG11DBEntityForMedia.findByMediaGroup",
                                                                   OG11DBEntityForMedia.class)
                                                 .setParameter("mediaGroupOid",mediaGroupOid.asString());
        Collection<OG11DBEntityForMedia> dbObjs = q.getResultList();

        return FindResultBuilder.using(securityContext)
                                .on(_modelObjectType)
                                .foundDBEntities(dbObjs)
                                .transformedToModelObjectsUsing(this);
    }
```
Imports:
- `java.util.Collection`
- `jakarta.persistence.TypedQuery`
- `r01f.model.persistence.FindResult`
- `r01f.model.persistence.FindResultBuilder`
- `r01f.model.security.context.SecurityContext`
- the OID.

### 6. CORE — Find delegate (Tier 2)
`OG11FindServicesDelegateForMedia` in `{…}.core.db.services.delegates.media`. Note that this class name has no `CORE`. Validate every parameter, then call the DAO:

```java
    @Override
    public FindResult<OG10Media> findByMediaGroup(final SecurityContext securityContext,
                                                  final OG10MediaGroupOID mediaGroupOid) {
        if (mediaGroupOid == null) throw new IllegalArgumentException("The media group oid cannot be null!");
        return this.getServiceImplAs(OG10FindServicesForMedia.class)
                   .findByMediaGroup(securityContext,
                                     mediaGroupOid);
    }
```
Imports: `FindResult`, `SecurityContext` and the OID, plus `r01f.util.types.Strings` for string parameters.

### 7. CORE — Find service (Tier 1)
`OG11COREFindServicesForMedia` in `{…}.core.db.services.media`. It only delegates: security and the entity manager are handled by the base class, and the logic belongs in Tier 2.

```java
    @Override
    public FindResult<OG10Media> findByMediaGroup(final SecurityContext securityContext,
                                                  final OG10MediaGroupOID mediaGroupOid) {
        return this.forSecurityContext(securityContext)
                   .createDelegateAs(OG10FindServicesForMedia.class)
                   .findByMediaGroup(securityContext,
                                     mediaGroupOid);
    }
```

In `OG99MockMediaFactory.create()`, set the field if it isn't set yet. There is no foreign key on the column, so a fresh OID is enough for the finder. Create a real group through the Client API (and delete it at the end of the test) only if the user wants the test to be realistic:

```java
        outObj.setMediaGroupRef(OG10MediaGroupRef.from(OG10MediaGroupOID.supply()));
```
In `OG99TestForMediaPersistence.doTestMediaPersistence()`, add a block after the load and before the update, replacing the `// add here a block for every custom finder…` placeholder:

## Step 5.2: Variants
Only the lines that differ from the example above.

**String, exact match** (the sample's `findByNameExact`):
- Parameter `final String name`.
- Column `@Column(name="NAME", nullable=true, insertable=true,updatable=true) @Basic` on `private String _name;`.
- Transfer delegate: `dbEntity.setName(modelObj.getName());`.
- JPQL `"WHERE dbMedia._name = :name"`; DAO `.setParameter("name",name)`.
- Tier 2: `if (Strings.isNullOrEmpty(name)) throw new IllegalArgumentException("The name cannot be null or empty!");`.

**String, contains / case-insensitive** (name it so: `findByNameContaining`):
- JPQL `"WHERE LOWER(dbMedia._name) LIKE :name"`; DAO `.setParameter("name","%" + name.toLowerCase() + "%")`.

**Enum** (e.g. a `OG10MediaType _type` field):
- Store the constant name as a string: column `TYPE` on `private String _type;`.
- Transfer delegate: `dbEntity.setType(modelObj.getType() != null ? modelObj.getType().name() : null);` (put the ternary on two lines if it's long).
- DAO `.setParameter("type",type.name())`; Tier 2 rejects a `null` type.

**Boolean** (e.g. `_active`):
- Column on `private boolean _active;`. It's primitive, so it's never `null`.
- Transfer delegate: `dbEntity.setActive(modelObj.isActive());`.
- JPQL `"WHERE dbMedia._active = :active"`; DAO `.setParameter("active",active)`; nothing to validate.

**Several fields** (e.g. `findByMediaGroupAndName`): one parameter, column and `setParameter` per field. Right-align each extra condition with `WHERE`:
```java
    @NamedQuery(name = "OG11DBEntityForMedia.findByMediaGroupAndName",
                query = "SELECT dbMedia " +
                          "FROM OG11DBEntityForMedia dbMedia " +
                         "WHERE dbMedia._mediaGroupOid = :mediaGroupOid " +
                           "AND dbMedia._name = :name")
```
Keep a space before each closing quote, so the concatenated clauses don't run together.

## Step 5.3: Removing a finder
1. First search the whole workspace for the method name: a REST resource, a UI or another component may call it through the Client API.
2. Remove it from the same eight places, from the test inwards to the API.
3. Remove the `@Column` and its copy in the transfer delegate only if no other `@NamedQuery` uses that column. Remove the `@Index` with it.
4. Tell the user that the column stays in the database.

## Step 5.4: Verify and report
- **Format.** Apply [`r01-java-formatter`](../../r01-java-formatter/SKILL.md) to the lines you wrote. It also right-aligns the `SELECT` / `FROM` / `WHERE` / `AND` of the `@NamedQuery`.
- **Check the chain by name:**
  - The method name and parameter list are identical in the interface, the DAO, the Tier 2 delegate and the Tier 1 service. They all implement the same interface, so a mismatch is a compile error.
  - The `@NamedQuery` name used in `createNamedQuery(...)` matches the one on the entity.
  - Every `:param` in the JPQL has a `setParameter("param",…)`.
  - Every JPQL path (`dbObj._mediaGroupOid`) is a field of the entity.
- **Imports.** Check that the ones you added resolve: `FindResult`, `SecurityContext`, the OID type, `Collection`, `Strings`, `TypedQuery`.
- **Report:**
  - The finder's signature and matching rule.
  - The files changed per layer.
  - The new columns and indexes, and that rows stored before the change have the column empty until they are updated again, so the finder won't find them.
  - What the user has to do: refresh and rebuild the projects (see "For every request" in `SKILL.md`) and rerun the persistence tests.
